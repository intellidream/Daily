## 1. Executive Summary

Phase P2 delivers robust, idempotent, and honest high-frequency telemetry ingestion across native iOS (DailyCore + watchOS) and Android (Jetpack Compose + Health Connect + Room + WorkManager).

Key accomplishments:
1. **Idempotent Ingestion & Schema v2 Alignment**: Both iOS and Android now populate `external_id`, `semantics`, `tz_offset_min`, and `local_date` on every ingested raw telemetry record. Deduplication occurs transparently at the database layer without dropping batches.
2. **Honest Data Guarantee**: Completely eradicated synthetic/demo trend generation (`generateHistoricalValue`) for authenticated users. Missing metrics faithfully present "—" or `0` rather than fabricated values (such as fake 07:15 wake times, synthetic daytime naps, or made-up RHR values).
3. **Android Room & Health Connect Architecture**: Resolved critical serialization bugs (ISO timestamp parsing for `timestamptz`), replaced hardcoded `"local_health_connect"` user identifiers with authenticated session IDs, wired two-way sync for dirty records, and scheduled background periodic sync via Android `WorkManager`.
4. **watchOS Granular Sleep & Telemetry**: Migrated the standalone Apple Watch app (`HealthTelemetryManager.swift`) from collapsing sleep into single `type: "sleep"` duration records to streaming granular sleep stages (`sleep_stage_deep`, `sleep_stage_rem`, `sleep_stage_light`, `sleep_stage_awake`) with sample UUIDs as `external_id`.
5. **Physical & Simulator Verification**: Rigorously validated UI, interactions, and data rendering on the booted iOS Simulator (`SimulaPhone`) and Android Emulator (`Medium_Phone_API_36.1`), confirming 1:1 visual fidelity with zero regressions.

## 2. iOS & watchOS Implementation Details

### 2.1 DailyCore Models (`DailyCore/Sources/DailyCore/Models/HealthModels.swift`)
- Evolved `HealthTelemetryRecord` to include Schema v2 fields:
  - `externalId: String?` (maps to `external_id`)
  - `sourceId: String?` (maps to `source_id`)
  - `semantics: String?` (maps to `semantics`: `"spot"`, `"interval_delta"`, `"session_stage"`)
  - `tzOffsetMin: Int?` (maps to `tz_offset_min`)
  - `localDate: String?` (maps to `local_date`)

### 2.2 HealthDataService (`DailyCore/Sources/DailyCore/Services/HealthDataService.swift`)
- **POSIX Timezone Fix**: Fixed `isoDateFormatter` to enforce `Locale(identifier: "en_US_POSIX")` with explicit `Calendar.current.timeZone`.
- **Telemetry Cloud Sync (`syncTelemetryToSupabase`)**:
  - Gated to authenticated users only (`AuthService.shared.isAuthenticated`).
  - Automatically filters out records generated by virtual computational engines (`DeviceSource.from(name: dev).isVirtualEngine`).
  - Chunks records into batches of 200 items to avoid payload limits and network timeouts.
  - Automatically enqueued as a background `Task` whenever `fetchLocalTelemetry` or `fetchLocalSleepStages` reads samples from Apple Health.
- **Idempotent Vitals Upsert**: Fixed `syncVitalsToSupabase` by adding explicit `onConflict: "user_id,date,type"`.
- **Today-Only Widget Snapshots**: Guarded `updateSleepSnapshot` and `updateStressSnapshot` with `Calendar.current.isDateInToday(selectedDate)` to prevent historic date navigation from corrupting Home Screen widgets.
- **Honest Trends**: Restricted `generateHistoricalValue` to explicit `-demoHealth` launch argument only; authentic users with missing history now receive `0.0` rather than synthetic data.

### 2.3 HealthKitManager (`iOS/Daily/Services/HealthKitManager.swift`)
- Implemented `fetchHourlyActiveEnergy(for: date)` using `HKStatisticsCollectionQuery` with `.cumulativeSum` and 1-hour interval components.
- Added deterministic `externalId`:
  - Step buckets: `"steps_hourly_\(epoch)"`
  - Active energy buckets: `"active_energy_hourly_\(epoch)"`
  - Discrete quantity samples: `sample.uuid.uuidString`
  - Sleep stage intervals: `sample.uuid.uuidString`
- Added explicit metric semantics:
  - `"interval_delta"` for step and energy intervals
  - `"spot"` for discrete heart rate, SpO2, and HRV samples
  - `"session_stage"` for sleep stage analysis intervals

### 2.4 watchOS Ingestion (`WatchOS/DailyWatch/DailyWatch Watch App/HealthTelemetryManager.swift`)
- Updated `TelemetryPayload` to include `external_id`, `semantics`, `tz_offset_min`, and `local_date`.
- Replaced monolithic `type: "sleep"` with exact canonical sleep stages:
  - `asleepCore` -> `sleep_stage_light`
  - `asleepDeep` -> `sleep_stage_deep`
  - `asleepREM` -> `sleep_stage_rem`
  - `awake` -> `sleep_stage_awake`
  - `asleepUnspecified` -> `sleep_duration`
- Tagged with `semantics: "session_stage"` and `unit: "seconds"`.
- Set `external_id = sample.uuid.uuidString` on all watch telemetry payloads for zero-loss, idempotent anchored queries.

## 3. Android Implementation Details

### 3.1 Model Layer & Serialization (`Android/core-model/src/main/java/com/intellidream/daily/model/HealthModels.kt`)
- Added `NullableTimestampSerializer : KSerializer<Long?>`:
  - Safely handles numeric epoch milliseconds, ISO-8601 strings (UTC `Instant` / `OffsetDateTime`), and date strings (`"yyyy-MM-dd"`).
  - Eliminates crashes when Supabase PostgREST returns ISO string `timestamptz` values.
- Annotated `startTime`, `endTime`, `createdAt`, `updatedAt`, and `syncedAt` across `HealthTelemetryRecord` and `VitalMetricRecord`.
- Added Schema v2 attributes: `externalId`, `sourceId`, `semantics`, `tzOffsetMin`, and `localDate`.

### 3.2 Database Layer (`Android/core-database`)
- Updated `HealthTelemetryEntity`:
  - Added columns `external_id`, `source_id`, `semantics`, `tz_offset_min`, and `local_date`.
  - Updated mapping functions `toRecord()` and `fromRecord()`.
- Bumped Room database version in `DailyDatabase.kt` from `6` to `7` with destructive fallback migration enabled.

### 3.3 Health Connect Integration (`Android/core-health/src/main/java/com/intellidream/daily/health/HealthConnectManager.kt`)
- Added `userId: String = "local_user"` parameter to `fetchTelemetryForDate(targetDate: Date, userId: String)`.
- Extracted `record.metadata.id` as `externalId` across Steps, Heart Rate, Resting Heart Rate, Sleep Stages, Active Calories, SpO2, HRV, and Hydration.
- Sleep stage duration canonicalized to seconds (`unit = "seconds"`).
- Populated `semantics`, `tzOffsetMin`, and local `yyyy-MM-dd` date strings.

### 3.4 Remote Networking & Synchronization (`Android/core-network/src/main/java/com/intellidream/daily/network/HealthRemoteService.kt`)
- **PostgREST ISO Filtering**: In `fetchTelemetryBetween`, converted start/end epoch milliseconds to standard ISO-8601 strings (`Instant.ofEpochMilli(...).toString()`) so PostgREST timestamp comparisons evaluate correctly without type errors.
- **Chunked Telemetry Push**: Added 200-record batch chunking and virtual engine filtering in `pushTelemetry`.
- **Vitals Upsert Conflict Resolution**: Configured `clientManager.client.postgrest["vitals"].upsert(vitals) { onConflict = "user_id,date,type" }`.

### 3.5 Health Repository & WorkManager Periodic Sync
- **`HealthDataRepository.kt`**:
  - Implemented `syncTelemetryToSupabase(telemetry)` and `syncVitalsToSupabase(vitals)` with local Room `markRecordsSynced` tracking.
  - Implemented `syncUnsyncedTelemetry()` and `syncUnsyncedVitals()` to drain offline dirty queues.
  - Honest trend generation in `loadHistoricalTrends`: matched by `m.rawKey` and `HealthMetricType.from(type)`; missing historic values default to `0.0` instead of `generateHistoricalValue`.
- **`HealthSyncWorker.kt` (`Android/app`)**:
  - Built a WorkManager `CoroutineWorker` scheduled periodically (every 1 hour with a 15-minute flex window and `NetworkType.CONNECTED` constraint).
  - Ingests latest telemetry for today and yesterday from Health Connect and drains unsynced local queues to Supabase.
  - Automatically updates all Glance widgets upon sync completion.
- **`DailyApp.kt`**:
  - Initialized `healthRepository.currentUserId = uid` during authenticated application startup.
  - Enqueued `HealthSyncWorker.enqueuePeriodicSync(this)`.
